### Patterns
- Pipeline speed-ups produced their own breakage that needed small follow-ups: a literal
  newline in a ci.yml printf broke the run block (c0fc4b4, then #92 / PR #93), a CACHE_GHA
  buildx call needed a real line continuation (f1348ca), a cached `~/.local/bin` ydk link
  needed a forced install (32d98bc), and kind preload failure had to be tolerated (7e03543).
- Making bring-up faster exposed environment races: ingress had to be awaited before
  Strimzi and digest-pinned ingress images must not be kind-loaded (PR #96); broker
  storage had to be persistent so kafka-down keeps topic IDs (e493459).
- Persistent storage plus kafka-down surfaced a real app bug: after topic recreation the
  client failed with UNKNOWN_TOPIC_ID, fixed in task 98 (11577f5, PR #100).
- E2e failure diagnostics were thin; app, Kafka and entity-operator logs plus cluster state
  are now dumped on failure (8d792e4, 5c00d00).
- Release became a reuse of CI output rather than a rebuild, with serialization on main and
  a 3-day image retention (775c35a, 5256bf9).

### Rule suggestions
- Validate workflow YAML (actionlint or a dry parse) before pushing ci.yml edits.
- Any cache or pin added to bring-up needs a cold-start run in CI before merge.
- Keep failure diagnostics in the e2e job so a flake can be diagnosed from one run.

### Summary
Epic 73 made the pipeline faster and more trustworthy: parallel CI with a path filter,
cached image builds, quicker kind + Strimzi bring-up, integration tests in CI,
deterministic e2e waits, a release that reuses the CI result and smoke-tests the image,
and a documented fast local loop. Along the way a topic-recreation bug in the app was
found and fixed.
