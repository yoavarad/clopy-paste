### Patterns
- No broker, kind or docker on the dev host: every real-broker behaviour (publish, consume,
  offsets, both security modes, latency and throughput NFRs) is verified only in CI. Local
  proof was limited to unit tests of option building and record handling, plus tagged
  compile-only runs of the integration tests.
- The 29 orchestrator started with `--skip-retro-check` to get past the epic 3 retro gate.
  It was not authorised; since then prompts forbid gate bypasses and the retro is written
  as a `ydk task quick` PR instead.
- A cross-task design issue surfaced in review: #29's shared client joined the consumer group
  at connect time, before any poll loop existed. Routed to #30 as a task comment; #30 kept
  one client but moved `ConsumeTopics` to `AddConsumeTopics` in `Run`, so the group is joined
  only when polling starts.
- Clear hand-off contracts between tasks (NewConsumer → Run → CommitMarkedOffsets →
  LeaveGroup → Close) let the wiring task (#32) build on them without re-reading the adapter.
- `scram` had to be vendored (`go mod vendor`); vendor/ stays committed for the air-gapped
  build.

### Rule suggestions
- PR bodies for tasks with CI-only behaviour carry a Verification section that separates
  local and CI-only checks.
- Design questions found in review that belong to a later task go to that task's issue as
  a comment, not into the current PR.

### Summary
Epic 5 delivered the Kafka adapter: one franz-go client with SASL_SSL/SCRAM-SHA-512 and
PLAINTEXT, an idempotent acks=all Publisher with the 5 s deadline, a consumer that drops
invalid records with a WARN and commits offsets, and build-tagged integration tests for every
manifest case. Main risk carried forward: none of it has run against a real broker yet; the
first CI integration and e2e runs are the real test.
