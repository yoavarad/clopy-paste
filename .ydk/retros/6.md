### Patterns
- Most of the epic is shell, chart and workflow code that the Windows dev host cannot run
  (no make, docker, kind, kubectl or trivy). Local proof was `sh -n`, `helm lint --strict`,
  chart render checks and stubbed dry runs; the real gates ran for the first time in CI.
- #34 wired `make e2e` into CI while the e2e cases were still TDD red stubs owned by #36/#37.
  Main and every open PR went red. #68 made the step `continue-on-error`; #37 must remove it.
  A task that turns on a gate must check that the gate can pass on main.
- Helm 4 removed `--atomic`; #34 switched `deploy.sh` to `--rollback-on-failure --wait` and
  updated ADR-011 (ydk bug #498 for the pack).
- The coverage gate went back to 80 in #34 (messaging 91.3%, httpapi 93.3%, config 86.9%).
- #65 conflicted with main after #63 and #64 merged; `git merge origin/main` with the
  bookkeeping merge driver resolved it with no code conflicts.
- Review findings fixed before merge: unpinned CI tool downloads now verified by SHA256, and
  release now requires the tag to be on main.
- Hand edits that `ydk ci init --force` would undo are marked with comments in ci.yml and
  .gitlab-ci.yml.

### Rule suggestions
- A task that enables a CI gate runs that gate against current main in its own PR and does
  not merge while the gate is red for reasons owned by a later task.
- PR bodies list hand edits to generated files that must be re-applied after regeneration.

### Summary
Epic 6 delivered validated configuration, main wiring with ordered graceful shutdown, chart
conformance (NetworkPolicy, probes, render checks), the image size gate and the full CI
pipeline (scan, e2e on kind + Strimzi, release, coverage and dependency gates). The pipeline
now builds, deploys both releases to kind and runs the e2e scripts; the e2e cases themselves
are the remaining gap (epic 7).
