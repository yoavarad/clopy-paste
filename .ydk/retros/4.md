### Patterns
- ydk's default `proof.screenshot_ref_patterns` includes `ydk:route:*`, so backend-only task
  27 (health routes) was blocked on screenshot proof. Fixed by limiting the patterns to
  `ydk:page:*` and `ydk:component:ui/*` (task 51).
- The epic retro gate blocked 25 and 26 at `ydk task start` once epic 3 closed. One
  orchestrator in another epic (29) bypassed it with `--skip-retro-check` before the rule was
  written down; later prompts forbid gate bypasses.
- Handler reviews missed requirement-level behaviour: neither PR tested ydk:req:messaging/lru-touch
  (GET touches an existing user; send never creates or touches one). Caught by checking the
  req manifests against the diff, then added as handler-level tests with the real store.
- PR #57 was merged before its follow-up test landed. `ydk task done` then opened a second PR
  (#60) for the same branch, which needed origin/main merged in to shrink to the new test.
- The two handlers shared the generated `handlers.go`. Putting each in its own file
  (send.go, get.go) and making health/middleware tests use a local panicking handler
  instead of a stub kept parallel PRs conflict-free.
- UTF-8 boundary checks noted in the epic 3 censor review were applied in both handlers
  (per-field for POST, the `user` query for GET) before censoring.
- `ydk task done` replayed a stale go-fmt failure from the verification cache (26); a new
  commit cleared it.

### Rule suggestions
- Reviewers check the diff against every `ydk:req` the task's components reference, not only
  the `ydk:test` cases.
- Merge a task PR only after its orchestrator reports done; follow-ups after a merge go
  through a new `ydk task quick`.
- UI-only screenshot proof; API routes are verified by tests.

### Summary
Epic 4 delivered the HTTP surface: send and read handlers with validation-before-censor,
request logging, JSON error format, health and readiness routes, and the single page with
polling and copy fallback. Manual browser checks on secure and insecure origins (PR #48) are
still pending before a release.
