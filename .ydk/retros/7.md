### Patterns
- Real behaviour only showed up on kind + Strimzi. #37 found that Strimzi rejects
  KafkaNodePool replicas 0, so kafka-down scales the cluster operator to 0 and deletes the
  broker pod, then resyncs KafkaTopic/KafkaUser. It also found an app bug: POST hung about
  35 s with the broker gone (franz-go holds in-flight records), fixed so Publish enforces
  its deadline via ctx.Done (d814ec6).
- E2e timing was flaky: #36 needed review fixes (escaped plain-text match, unique censoring
  data, per-message LRU waits), #37 hardened the restart-resume watch and the network-policy
  probe retry (407a804), and #80 (PR #86, follow-up #99) moved the functional cases to
  deterministic waits and run-scoped data.
- Follow-ups from the e2e work: #79 ran the integration-tagged Kafka tests in CI (PR #89);
  #92 fixed a literal newline in a ci.yml printf that broke the run block (PR #93); #94
  merged #37 after both.
- Windows dev host gotchas: the pre-push hook runs `go test -race`, which needs WinLibs
  mingw64/bin on PATH plus `CGO_ENABLED=1` and `PYTHONUTF8=1`.
- The verification cache can replay a stale go-test FAIL (clear `.ydk/cache/verification`),
  and helm-lint can crash on non-UTF-8 output.
- The epic-retro gate blocked starting later tasks because `ydk memory retrospective` needs
  ANTHROPIC_API_KEY; the retro is written by hand as a `ydk task quick` PR, not bypassed.

### Rule suggestions
- Destructive e2e cases run last with run-scoped users, and every wait polls a condition
  instead of sleeping.
- Document the Windows toolchain env (mingw64 on PATH, CGO_ENABLED=1, PYTHONUTF8=1) next to
  the pre-push hook.

### Summary
Epic 7 delivered the end-to-end verification: six functional round-trip cases, the smoke
round trip, and latency (P95 <= 5 s), pod-health, network-policy, Kafka-outage and
restart-resume checks. The CI `make e2e` step is blocking again. Running the cases on kind
exposed a real publish-deadline bug and several timing races, all fixed.
