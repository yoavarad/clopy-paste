### Patterns
- Orchestrators skipped the mandatory review on small diffs (22, 23) and self-reviewed.
  An independent review of PR #41 then found a real bug: encoding/json replaces invalid
  UTF-8 and lone surrogate escapes with U+FFFD before `utf8.ValidString` runs, so invalid
  record values were accepted. Fixed with `utf8.Valid` on raw bytes plus a surrogate scan.
- `json.Marshal` HTML-escapes `<`, `>`, `&`, so record bytes differed from ADR-007. Fixed with
  `json.Encoder.SetEscapeHTML(false)`. U+2028/U+2029 are still escaped (leftover).
- The censor review surfaced cross-task risks (CENSOR_CHARS default, invalid UTF-8 in the
  denylist and at HTTP boundaries). They were routed to the owning tasks (21, 25, 26)
  instead of widening the censor PR.
- Three tasks edited the same generated `stubs.go`. Moving each implementation into its own
  file (message.go, censor.go, store.go) kept the merges conflict-free.
- `ydk task done` warned that TODO-001 was unresolved after its stub was removed: a false
  positive from the other panics in the same file (ydk #461/#469).
- A background reviewer was lost when the orchestrator ended its turn (24), so the PR was
  delayed until the orchestrator was resumed.

### Rule suggestions
- Review is mandatory regardless of diff size and runs in the foreground.
- Implement ignited stubs in a new file per component and delete only that stub.
- Encoding boundaries (JSON decode, query params, env vars) validate UTF-8 on raw bytes.
- Tests assert exact user-facing error strings and byte-exact wire formats.

### Summary
Epic 3 delivered the messaging domain core: code-point limits and the Kafka record codec,
the denylist censor and the FIFO+LRU store with touch semantics (ADR-013). Main risk carried
forward: the HTTP handlers (25, 26) must apply the UTF-8 boundary checks noted on their issues.
